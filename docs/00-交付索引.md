# 00 · 交付索引与要求对照

本目录按实训任务的 5 项交付要求组织，并额外对照 FDE 训练中心「业务挖掘」阶段的 7 项评分要点。

## 一、对任务的 5 项要求

| # | 要求原文 | 交付物 | 完成情况 |
|---|---|---|---|
| 1 | 业务挖掘：实验室系统生成 | `01-业务挖掘.md` | 按实验室 3 个行动项（识别业务机会 / 建立现状基线 / 确认立项与决策链）输出，含业务机会清单、五项指标基线、项目章程与干系人地图、四来源收敛、15 条证据台账、7 项待核实问题 |
| 2 | 行业分析：docx 文档整理 | `02-行业分析.docx`（源文 `02-行业分析.md`） | 8 章、5 页：规模与政策、业态结构、共性痛点、标杆实践、技术供给与价格带、启示与风险、结论 |
| 3 | 两张流程图：现状、数智化转型后 | `03-流程图-现状.png/.svg`、`03-流程图-数智化转型后.png/.svg`、`03-流程图-源文件.md` | 泳道图，各 11–13 个节点，标注人工转录点、口径不一致点、硬约束与人工升级节点；附 mermaid 源码便于修改 |
| 4 | 报价单、设计方案 | `05-报价单.xlsx`、`05-报价说明.md`、`04-设计方案.md` | 三档报价（30.1 / 65.6 / 125.4 万，含明细、条款、假设）+ 方案比较、架构、算法、数据契约、权限矩阵、评估计划、风险表 |
| 5 | 完成一个最小的 MVP | `../mvp/` | 可运行的单页系统：缺货上报 → 建议量 → 硬约束 → 例外复核 → 下发/调拨 → 收货 → 指标与审计，规则引擎可用 node 单测 |

## 二、对照实验室评分要点（7 项）

| 评分要点 | 对应位置 | 说明 |
|---|---|---|
| 证据完整性（事实 / 证据编号 / 待验证项） | `01` 第 5 节证据台账（EV-01 ~ EV-15）+ P-01 ~ P-07 | 估算值一律标注「待验证」，不写成事实 |
| 上游承接（编号与版本边界） | `04` 开头「上游」字段；`04` 第 11 节与 MVP 映射 | 全程沿用 OP-x / V-x / P-x / EV-xx，未另起编号 |
| FDE 方法（工作流拆解 / 结果风险矩阵 / 四来源收敛） | `01` 第 4 节四来源；`04` 第 2 节方案比较（价值 × 风险 × 可撤销性） | 三套框架都用上了，且结论一致指向同一瓶颈 |
| 业务结果（动作 → 结果 / 口径 / 样本 / 责任人） | `01` 第 2 节指标表；`04` 第 8 节评估计划 | 每项指标都有分子分母、时间窗、样本量、责任人 |
| 风险与边界（异常 / 权限 / 人工交接 / 停止条件） | `04` 第 4.2 节硬约束、第 6 节人工节点、第 8.3 节停止条件、第 10 节风险表 | 越权、超时、缺数据、重复请求均有处置路径 |
| 下一阶段可执行性 | `01` 第 6 节「交给下一阶段的输入」；`04` 第 9 节里程碑 | 可直接进入阶段 2 现场调研与阶段 5 构建 |
| 立项判断（为什么现在做、谁决定） | `01` 第 3 节项目章程 + 立项判断 | 明确发起人、审批人、预算与停止权 |
