## 一、人工现状流程（没有 AI）

**触发**：门店缺货（缺货率 12%，`retail-f00`）。

```
门店巡店发现缺货
  → 微信群 / 电话口头报数（38% 消息无明确数量）
  → 计划员导出 Excel 手工汇总销量与库存
  → 凭经验手工算建议量（不分「有货」与「可售」，账实差异平均 8%）
  → 忽略整箱 / 起订量 / 线路容量约束（周一三五固定配送，小门店仓容有限）
  → 促销临时变价 / 节假日客流使预测失效
  → 生成补货单（多版本 v3 → v5 → v7，无留痕）
  → 仓配核对在途 / DC 库存（与门店表不一致）
  → DC 不足时电话协调跨店调拨（靠人情，无评分）
  → 门店收货后手工改库存表（账实长期不符）
  → 数量 / 效期差异微信群反馈、事后补单（无审批痕迹）
```

**结构缺陷（三处）**：

1. **有货 ≠ 可售**：货在后仓但货架没补，系统仍算有库存，消费者看到空货架（`retail-f10`、`retail-f12`）。
2. **缺货截断被误读**：销量为零可能是缺货截断，不是没人买（`retail-f31`）。
3. **约三成延迟补货是配送排队**，不是预测问题（`retail-f51`）。

**人工责任边界**：全量人工核对，每张单靠计划员逐个过；补货量凭老员工直觉；缺货靠电话人情；单据版本无系统记录。

**量化口径（现状）**：缺货率 12%、周转 48 天、账实差异 8%、无审批留痕、处理时长与返工无系统统计。

## 二、数字化新流程（增加 AI 后）

**触发**：系统按快照自动识别缺货（每天两次刷新，`retail-f34`）。

```
① AI 自动汇聚数据
   → 06:30 / 14:30 生成 POS / 库存 / 在途 / 效期快照（带版本号）
② AI 识别缺货 + 治理口径
   → 区分「可售库存」与「账面库存」；识别缺货截断（销量零≠没人买）
   → 新旧码 / 套装码归并
③ AI 生成需求基线
   → 近 7 日日均 + 波动 CV → 置信度三档（高 / 中 / 低）
④ AI 计算建议量（内置硬约束）
   → 安全库存 + 陈列覆盖 + 整箱规格 + 最小起订量 + 线路容量
⑤ AI 硬约束校验
   → 效期 / 库存上限 / 权限 / 重复 / 数据新鲜度 / 兜底触发
⑥ 判断：高置信且无异常？
   ├─ 是 → 批量流转（计划员抽检）
   └─ 否 → 例外复核（medium / low 置信、改量必填理由）
⑦ 人工签核后一键下发补货单（带快照 ID + 规则 ID + 签核人）
⑧ 调拨评分 / 门店可见到货
   → DC 不足 → 5 因子评分调拨（区域物流审批）
   → 门店看到预计到货与未满足数量，减少无效催货
⑨ 扫码收货 → 差异自动开异常单 → 审计日志全程可重建
⑩ 指标看板：缺货率 / 周转 / 报废（促销期单列误差），口径唯一
```

**与人工流程的差异**：

| 环节 | 人工现状 | 数字化新流程 |
|---|---|---|
| 缺货信号 | 口头 / 微信，38% 无数量 | 系统识别 + 可售口径治理，结构化入库 |
| 算量 | 手工 Excel，凭经验 | 规则引擎统一公式 + 整箱 / 起订量 / 线路容量约束 |
| 促销 | 变价使预测失效，无结构化字段 | 促销版本结构化随建议传递，促销期单列误差 |
| 校验 | 事后追责 | 事前硬约束（效期 / 上限 / 权限 / 重复 / 新鲜度）+ 兜底阻断 |
| 复核 | 全量人工核对 | 只审例外，高置信批量流转 |
| 调拨 | 电话协调、靠人情 | 5 因子评分 + 区域物流审批 + 留痕 |
| 门店可见 | 看不到分配依据 | 可见预计到货与未满足数量 |
| 收货 | 手工改表，账实长期不符 | 扫码收货，差异自动开异常单 |
| 审计 | 无留痕 | 兜底 + 审计日志，每单可重建 |
| 指标 | 口径不一 | 看板实时，缺货 / 周转 / 报废并列，促销期单列 |

**人工责任边界（不可自动化）**：正式下发由具名人员签核；跨店调拨需区域经理批准；自动采购不直接上线；供应商合同不在改动范围；兜底触发后的恢复动作必须人工确认。

## 三、如何重新导出图片

```bash
python3 tools/gen_flow.py          # 生成 docs/*.svg（纵向 + 三栏版式）
python3 - <<'EOF'
import pymupdf
for f in ["docs/03-流程图-现状.svg", "docs/03-流程图-数智化转型后.svg"]:
    d = pymupdf.open(f)
    d[0].get_pixmap(dpi=150).save(f.replace(".svg", ".png"))
EOF
# jpg 版（供网页/演示用）
python3 - <<'EOF'
from PIL import Image
for n in ["03-流程图-现状", "03-流程图-数智化转型后"]:
    Image.open(f"docs/{n}.png").convert("RGB").save(f"docs/{n}.jpg", "JPEG", quality=92)
EOF
```
